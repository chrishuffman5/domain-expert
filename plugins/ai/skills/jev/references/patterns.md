# Architectural patterns for building with jev

Read this when deciding where jev sits in an application: fan-out, screening, routing, gating, composite ranking, or pairing with an LLM. All named patterns are TypeSafe's (six on the current patterns index). Runnable code for each: `examples.md`.

## Governing principle

> Source: https://docs.typesafe.ai/concepts/how-to-build-with-system-one.md (fetched 2026-09-23)
> Source: https://typesafe.ai/blog/dont-call-it-a-decision-model (vendor blog)
> Source: https://docs.typesafe.ai/cookbooks/sde_cascade.md

- "Keep code in control; use AI only for narrow, structured decisions." Vendor phrasing since November: "Jev makes judgments, code makes decisions." Control flow, arithmetic, dates and thresholds stay in code.
- **Decompose.** Ask one narrow question per rule rather than "is this answer right?": a flag then names the rule that broke, and each question can be reworded or re-thresholded alone (SDE-cascade cookbook calls this "The TypeSafe Way").
- Questions in one request are independent; they share the state, not hidden context.
- Vendor latency figures: 70–500 ms end-to-end (launch post); in the content-audit demo the median request took 144 ms with 1 question and 151 ms with 45.

## Speculative fan-out

> Source: https://docs.typesafe.ai/patterns/fan-out.md
> Source: https://docs.typesafe.ai/demos/smart-home.md

Put every question you *might* need in one request; code reads only the relevant answers. Support triage asks for the category plus bug severity and reproducibility (only relevant for bugs), refund intent (only for billing) and frustration (always), in one call. The smart-home demo asks "what action on the lights?" before anything confirms the request targets lights. Splitting into sequential calls minimises questions but is slower and more expensive, because each call re-reads (and re-bills) the state.

## Screen with a Noul first (NEW)

> Source: https://docs.typesafe.ai/patterns/noul-screen.md

Ask one Noul with a small state, and run the expensive step only on a clear yes. Worth the extra request only when the next step costs something the first does not: **a bigger state** (code must fetch the customer record or attachment), **a slower model** (an LLM call) or **a person**. Otherwise prefer fan-out.
- Thresholds: > 0.7 yes, < 0.3 no, and the band between gets **its own outcome** (a quick human look), never rounded.
- Shared-inbox example (`expects_reply`): the overdue-desk message 0.98 → full triage; "just so you know, one screw was missing, I had a spare" 0.44 → quick look; thank-you 0.10, newsletter 0.02, receipt 0.02 → filed.
- Variants: check a cheap step's output with a Noul and escalate only failures; chain several screens (English? about our product?).

## Companion Noul (NEW)

> Source: https://docs.typesafe.ai/patterns/companion-noul.md

A Choice always picks an option, even when none applies. Add a Noul to the same request asking whether any option fits, and trust the Choice only on a clear yes **and** a high top probability (example bar 0.7); otherwise route to a generalist with the Choice's pick as a hint. Recorded on jev-1.14.0: a desk-lamp complaint picked `desk_pro` at 0.96 with confidence 0.94, but the Noul read 0.02.
- CHANGED: the vendor now says an `other` option "falls short": it competes for probability and splits mixed inputs. The companion Noul "usually works better".
- Variants: one Noul per option when inputs can match several; candidates generated by code (regex) with a Noul asking whether the right value is among them.
- Box has the same always-answers problem; pair it with a Noul.

## Routing by confidence (Score)

> Source: https://docs.typesafe.ai/patterns/confidence-routing.md

Check Score confidence before reading the score. Bug-severity example (five levels, cosmetic → critical): confidence < 0.5 → triage by a person; else score < 1.5 backlog, < 2.5 sprint, otherwise page on-call. A "notes gone after the update, or maybe deleted" report scored 3.19 (which alone would page on-call) at confidence 0.34 and went to triage.
- When the action depends on which side of a level boundary the answer falls, sum the probabilities on that side (`p[3] + p[4] >= 0.3` → message on-call), because Score confidence counts neighbouring-level mass as only a small spread.

## Routing by probability (NEW; replaces intent routing)

> Source: https://docs.typesafe.ai/patterns/probability-routing.md

Give riskier actions higher probability thresholds, and give below-threshold answers their own outcome. Voice-banking example: `likelihood = probabilities[choice]`; < 0.7 on any action → human; `check_balance` at ≥ 0.7 → show it; `approve_transfer` > 0.9 → **open a confirmation screen** (never move money directly), else ask the user to clarify.
- Even a hesitant "Um, the transfer thing... yeah, go ahead I guess" got 0.99 for `approve_transfer`: probability says *which* action, not that the user checked the details. Keep a human confirmation on irreversible steps.
- For a Choice, threshold the probability, not `confidence` (confidence is computed from the top probability and adds nothing).
- The old "intent routing" page now serves this content.

## Composite scoring

> Source: https://docs.typesafe.ai/patterns/composite-scoring.md

One Score per dimension, normalise to 0–1 (`score / 4` for five levels), weight in code. Resume example: Senior IC = 0.40 Python + 0.10 leadership + 0.40 system design + 0.10 generalist; Engineering Manager = 0.15 / 0.40 / 0.20 / 0.25. Re-weighting needs no new model calls and the arithmetic stays reviewable.

## Shortlist, then score (large candidate sets)

> Source: https://docs.typesafe.ai/demos/airbnb-listing-search.md
> Source: https://docs.typesafe.ai/cookbooks/infinite_cardinality_choice.md

- Airbnb demo: 1,000 listings in groups of 100, one Choice per group over listing ids (all in parallel), keep the top 5 per group, then one request with a Score per shortlisted listing. 11 requests instead of 1,000, about one second, inside Google Sheets' 30-second custom-function limit.
- Infinite-cardinality cookbook: one Noul per film on a short plot, again on a long plot for the top 80, then one Choice over the top 20 (right film first 78% of the time vs 33% with an embedding shortlist).

## Classification with a hierarchy fallback

> Source: https://docs.typesafe.ai/cookbooks/classification_using_confidence.md

One Choice over 75 SIC industry groups; at confidence ≥ 0.9 report the group, below it report the parent division (derived in code, no second call). Over 60 filings: the 28 confident answers were right 93% of the time, the other 32 only 50%, rising to 78% one level up.

## Hybrid with a generative LLM

> Source: https://docs.typesafe.ai/demos/smart-home.md
> Source: https://docs.typesafe.ai/cookbooks/verify_llm_outputs.md
> Source: https://docs.typesafe.ai/cookbooks/sde_cascade.md
> Source: https://docs.typesafe.ai/cookbooks/llm_guardrails.md

jev never writes text. Hand prose, code or decomposition to an LLM:
- **Decompose then judge**: a Noul flags a compound request; an LLM splits it; each part goes back through jev. A conversational request falls back to a chat LLM.
- **Verify an LLM's answer**: three Nouls (`answerable`, `declines`, `supported`) give a risk score; ≥ 0.2 goes to review. On 1,000 multi-hop questions answered by `gpt-6-luna` (88.5% correct), the check passed 73% of answers at 95.7% accuracy and caught 84 of 115 wrong ones.
- **Cascade**: a cheap model extracts, jev checks each rule (`P(broken)` > 0.7 escalates), and only failures go to a reasoning model.
- **Guardrails on both sides**: a battery of hazard Nouls plus a harm Score screens the user message *and* the model reply; your thresholds decide pass, review, block or support.
- Agent frameworks: LangChain `ModelRouterMiddleware` picks the cheapest capable model per run; Pydantic AI `FallbackModel` hands unsure routes to an LLM; Vercel AI Gateway decision fallbacks re-run uncertain decisions on another model.

## Agent-assisted adoption (TypeSafe's own coding-agent skill)

> Source: https://docs.typesafe.ai/agent-skill.md
> Source: https://docs.typesafe.ai/introduction/coding-agents.md

- jev is **not** a replacement for the LLM behind Claude Code, Cursor or Copilot; there is no `model: "jev-latest"` setting for a coding agent. Use the coding agent to write code that calls jev.
- Install: `claude plugin marketplace add typesafe-ai/skills` then `claude plugin install typesafe@typesafe-ai` (invoke `/typesafe:typesafe-ai`), or `npx skills add typesafe-ai/skills --skill typesafe-ai`. Update with `claude plugin marketplace update typesafe-ai` and `claude plugin update typesafe@typesafe-ai`.
- Vendor directives: keep questions and threshold constants in one file ("agents aren't great at writing questions, so expect to edit collaboratively"); when routing misbehaves, check thresholds and question specificity first; a stale skill makes agents invent request or response fields.
