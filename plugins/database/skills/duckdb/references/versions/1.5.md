# DuckDB 1.5

This reference covers DuckDB 1.5 (codename "Variegata"), first released March 9, 2026, with over 6,500 commits from close to 100 contributors since v1.4. DuckDB 1.5 introduced the VARIANT type, a built-in GEOMETRY type, a redesigned CLI, an opt-in experimental PEG parser, an ODBC scanner extension, Azure writes, a curl-based httpfs backend, and -- in the v1.5.3 patch -- the Quack remote protocol (beta).

**Support status (as of 2026-11-13):** no longer current -- **2.0.0 LTS** (2026-10-21) is. 1.5 is formally **non-LTS**, but its community support was extended to **2027-03-01** (the 2.0 announcement calls it "effectively an LTS"). There was no 1.6: the release after 1.5.x is 2.0.0. Use 1.5 as the staging line for anything leaving 1.4 (EOL 2026-11-17) that is not yet ready for 2.0. See `references/versions/2.0.md` for the 1.5 -> 2.0 checklist.

## Key Features Introduced in DuckDB 1.5

> Source: https://duckdb.org/2026/03/09/announcing-duckdb-150.html

### VARIANT Type

> Source: https://duckdb.org/2026/03/09/announcing-duckdb-150.html
> Source: https://duckdb.org/docs/2.0/sql/data_types/variant.html

VARIANT stores typed, binary data with per-row type information; JSON is stored as text. One column can hold different types per row:

```sql
CREATE TABLE events (id INTEGER, data VARIANT);

INSERT INTO events VALUES
    (1, 42::VARIANT),
    (2, 'hello world'::VARIANT),
    (3, [1, 2, 3]::VARIANT),
    (4, {'name': 'Alice', 'age': 30}::VARIANT);

SELECT id, variant_typeof(data) FROM events;
SELECT variant_extract(data, 'name') FROM events WHERE id = 4;   -- or data.name
```

**What 1.5 shipped vs. 2.0:**
- 1.5: the type, `variant_typeof`, `variant_extract`, dot-notation access, and reading VARIANT from Parquet including shredded files.
- 2.0: shredding of VARIANT columns inside DuckDB database files, shredded Parquet *writes*, extraction pushdown, and the full `variant_*` function set. For VARIANT-heavy workloads, prefer 2.0 -- see `references/versions/2.0.md`.

Never quote a "100x faster than JSON" figure: no official source supports it. The 1.5.0 post says only that per-row typing helps compression and query performance.

### Built-in GEOMETRY Type

> Source: https://duckdb.org/2026/03/09/announcing-duckdb-150.html

DuckDB 1.5 moves the GEOMETRY type from the spatial extension into core:

```sql
CREATE TABLE locations (id INTEGER, name VARCHAR, geom GEOMETRY);
CREATE TABLE places (geom GEOMETRY('OGC:CRS84'));   -- optional CRS parameter

-- The spatial extension still provides the function library
INSTALL spatial;
LOAD spatial;
```

- Stored as little-endian WKB; per-row-group statistics (bounding box, geometry types) enable pruning; `&&` benefits.
- Optional shredding cuts on-disk size about 3x for uniform columns such as point clouds (`geometry_minimum_shredding_size`).
- Axis order: `geometry_always_xy` -- 1.5 warns unless set to true; the 1.5.0 post says 2.0 turns the warning into an error unless the setting is false, and 2.1 defaults it to true.
- The spatial extension registers more than 7,000 EPSG coordinate reference systems.

### Friendly CLI

> Source: https://duckdb.org/2026/03/09/announcing-duckdb-150.html

- Dark/light color palette (`.highlight_colors`), dynamic prompts showing the current database and schema.
- `.tables` lists catalogs/schemas/columns; `DESCRIBE` for one table; `_` refers to the last result.
- Built-in pager above 50 rows.
- Since 1.5.0 the CLI stores logs in `shell_log_storage` (printed, not queryable); run `CALL enable_logging(storage = 'memory');` to query `duckdb_logs`.

### PEG Parser (Experimental, Opt-in)

> Source: https://duckdb.org/2026/03/09/announcing-duckdb-150.html
> Source: https://duckdb.org/docs/2.0/sql/peg_parser.html

```sql
-- 1.5 only: opt in to the experimental parser for this session
CALL enable_peg_parser();
```

- In 1.5 the PostgreSQL-derived parser is the default and PEG is experimental, with a slight millisecond-level overhead.
- `SET pg_experimental_parser = ...` is not a real setting -- never use it.
- In 2.0 PEG is the default and `enable_peg_parser()` is "no longer required or available"; the old parser is reachable via `SET enable_legacy_parser = true;`. Running a workload under `CALL enable_peg_parser();` on 1.5 can surface parse failures early, but the 1.5 parser was experimental -- always re-test on 2.0 itself, and check the silent result changes listed in `references/versions/2.0.md`.

### ODBC Scanner Extension

> Source: https://duckdb.org/2026/03/09/announcing-duckdb-150.html
> Source: https://duckdb.org/docs/2.0/core_extensions/overview.html

DuckDB 1.5 ships an ODBC scanner extension for querying ODBC data sources from DuckDB. The 1.5.0 post loads it as `LOAD odbc_scanner;` and names the functions `odbc_connect` and `odbc_query`. The 2.0 catalog lists the extension as `odbc` (alias `odbc_scanner`, secondary tier). Check the extension docs for exact signatures -- they were not part of the release post. (Distinct from DuckDB's own ODBC *driver*, which lets other tools connect to DuckDB.)

### read_duckdb Table Function

> Source: https://duckdb.org/2026/03/09/announcing-duckdb-150.html

`read_duckdb` reads DuckDB database files without attaching them first, and supports globs:

```sql
SELECT * FROM read_duckdb('numbers*.db');
```

### Azure Write Support

> Source: https://duckdb.org/2026/03/09/announcing-duckdb-150.html
> Source: https://duckdb.org/docs/2.0/core_extensions/azure.html

DuckDB 1.5 writes to Azure Blob Storage and ADLS Gen2 with `COPY`:

```sql
INSTALL azure;
LOAD azure;
CREATE SECRET (TYPE azure, PROVIDER credential_chain, ACCOUNT_NAME 'myaccount');

COPY orders TO 'az://container/path/orders.parquet' (FORMAT PARQUET);
COPY orders TO 'abfss://container/output/' (FORMAT PARQUET, PARTITION_BY (region));
```

- Schemes: Blob `az://` or `azure://`; ADLS `abfss://` or `abfs://`.
- Prefer `TYPE azure` secrets; `azure_storage_connection_string` / account-name variables are in the docs' deprecated "Authentication with Variables" table.
- Since 1.5.4 the extension buffers writes and uploads in blocks; read chunk/buffer defaults rose to 8 MiB.

### httpfs Network Stack

> Source: https://duckdb.org/2026/03/09/announcing-duckdb-150.html

The default httpfs backend changed from httplib to curl (OpenSSL remains the TLS library); `http_timeout` and `http_retries` still apply. Extension installs go over https://. (Connection pooling and async I/O settings such as `http_client_pool_capacity`, `async_threads`, `read_ahead_depth` arrived in 2.0.)

### Lance Lakehouse Format

> Source: https://duckdb.org/2026/03/23/announcing-duckdb-151.html
> Source: https://duckdb.org/docs/2.0/core_extensions/overview.html

The 1.5.1 post announced Lance read/write via the `lance` extension, also available for 1.4.4 LTS and 1.5.0:

```sql
INSTALL lance;
LOAD lance;
SELECT count(*) FROM 'example.lance';
COPY (SELECT * FROM orders) TO 'example.lance' (FORMAT lance);
```

The 2.0 core-extension catalog lists `lance` as **third-party** (no support tier).

### Quack Remote Protocol (v1.5.3, beta)

> Source: https://duckdb.org/2026/05/20/announcing-duckdb-153.html
> Source: https://duckdb.org/docs/2.0/quack/overview.html

DuckDB 1.5.3 ships **Quack**, an HTTP-based RPC protocol that turns DuckDB processes into a client and a server, autoinstalled and autoloaded on first use. At 1.5.3 it was explicitly beta ("protocol, function names, and similar details may still change"), with a production version planned for 2.0.

```sql
-- Server (default port 9494, binds localhost)
CALL quack_serve('quack:localhost', token = 'super_secret');
CALL quack_stop('quack:localhost');

-- Client
FROM quack_query('quack:localhost', 'SELECT 42', token = 'super_secret');
CREATE SECRET (TYPE quack, TOKEN 'super_secret', SCOPE 'quack:localhost');
ATTACH 'quack:localhost' AS remote;
```

- 1.5.x lacks the 2.0 additions: `CONNECT` / `DISCONNECT`, `duckdb -serve` / `-connect`, and the performance and stability work.
- On 2.0, non-local servers serve HTTPS with a self-signed certificate by default. Either way, front non-local servers with a TLS-terminating reverse proxy and never expose Quack directly.
- Even on 2.0 the Quack FAQ says the protocol is not yet stable: never mix 1.5.3 and 2.0 Quack peers without testing.

For the full setup, security model and hardening checklist, load `references/quack.md`.

### DuckLake 0.4 Highlights (not core storage features)

> Source: https://duckdb.org/2026/03/09/announcing-duckdb-150.html

The 1.5.0 post lists sorted tables, deletion inlining and partial delete files as features of the **DuckLake 0.4 specification**, not of DuckDB's native storage. DuckDB 1.5.2 then added DuckLake 1.0 support. DuckLake 1.1 requires DuckDB 2.0.0+.

## Migration from DuckDB 1.4 to 1.5

> Source: https://duckdb.org/2026/03/09/announcing-duckdb-150.html
> Source: https://duckdb.org/docs/2.0/internals/storage.html

1. **Non-LTS, but supported to 2027-03-01** -- longer than 1.4 LTS (EOL 2026-11-17).
2. **Extensions** -- binaries are version-specific; run `UPDATE EXTENSIONS;` after upgrading.
3. **Storage format** -- 1.0 through 1.5 write storage version 64 by default, so 1.4 and 1.5 can open each other's default files.
4. **Behavior changes in 1.5.0** -- `date_trunc` on DATE returns TIMESTAMP; single-arrow lambdas (`x -> x + 1`) emit a deprecation warning (`lambda_syntax` setting) and are disabled by default in 2.0; httpfs backend switched to curl.
5. **GEOMETRY in core** -- spatial functions keep working; the type no longer needs the extension.

```bash
# 1. Back up with the old binary
duckdb my_database.duckdb "EXPORT DATABASE 'backup_pre_1.5' (FORMAT PARQUET)"

# 2. Install DuckDB 1.5 (latest patch: 1.5.6)
pip install duckdb==1.5.6

# 3. Update extensions and verify
duckdb my_database.duckdb "UPDATE EXTENSIONS;"
duckdb my_database.duckdb "SELECT version(); PRAGMA database_size;"
```

## When to Choose DuckDB 1.5 (as of November 2026)

> Source: https://duckdb.org/release_calendar

Choose 1.5 when:
- You must leave 1.4 before its EOL (2026-11-17) but cannot yet validate 2.0's breaking changes (storage version 69, PEG parser, lambda syntax, transaction aborts).
- A 1.x-only consumer must keep reading files you write (1.x cannot open 2.0-format files unless you pin the storage version).

Choose 2.0 LTS for everything else: it is the current release, the LTS line until about October 2027, and the only line with polished Quack, async I/O, VARIANT shredding and triggers.
